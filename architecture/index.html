Systems Philosophy

Infrastructure Is a Reflection of Judgment

I operate a segmented, 10Gb, GPU-backed private AI fabric — not as a hobby, but as a proving ground for the systems I design for regulated environments. Every architectural decision here maps to a production pattern I'd deploy for a customer.

Trust zones enforce lateral movement boundaries. Inference workloads run on an isolated plane. Governance primitives sit between agents and the tools they call. The question isn't whether the system works — it's whether the system survives scrutiny.

  • Segmented VLAN trust zones with zero-trust inter-VLAN policy enforcement
  • Isolated inference plane — GPU workloads separated from general compute
  • Kubernetes workload fabric across a 3-node HA cluster
  • Cryptographic identity for every service, no implicit trust
  • Immutable infrastructure — nothing is patched in place

Systems should fail safely.

They should scale intentionally.

They should survive audit.

Infrastructure Proof

How This Site Is Deployed

This site is a static export. It is compiled to plain HTML at build time and served from a CDN edge — there is no origin server, no container, and no runtime to fail.

An earlier version ran on managed containers behind a load balancer, with VPC isolation and infrastructure-as-code. It was a good demonstration of those patterns and a bad way to host four pages of prose: the app cost almost nothing while the load balancer and NAT gateway cost the most, and any control-plane mistake took the whole site down. A portfolio that can return an error page is a weaker argument than one that cannot. So the demonstration moved to where the complexity actually earns its keep, and the front door became undestroyable.

Delivery Properties

BuildGitHub Actions — lint, unit tests, static export on every PR
OutputPlain HTML, CSS, and JS in an immutable artifact
ServingCDN edge, no origin server, nothing to patch or restart
TLSManaged certificates, automated renewal, HSTS at the edge
DeployMerge to the release branch — the artifact is the deploy
RollbackRevert the commit; the previous artifact republishes
StateNone. No database, no session store, no cookies
CredentialsNone in the build or the served artifact

Where the Complexity Went

The infrastructure work this site used to advertise still exists — it just runs where it is load-bearing, behind a private estate rather than beneath a brochure. Aggregates, because the details are not a marketing surface:

Engines198 repositories under active management
Services103 running — containers, supervised agents, resident daemons
Devices628 catalogued across three sites, identity-resolved past MAC rotation
Zones14 segmented trust zones, per-tier firewall policy
OperatorsOne

The dated record of what was built on it is at the done log.

CI/CD Pipeline

Pull requests run lint, the unit suite, and a production build — a build that fails to export never reaches the branch. Merge publishes the exported artifact. There is no deploy step that can drift from the source, because the artifact is the source compiled.

A synthetic probe runs on a schedule against the live host, checking real routes rather than a health endpoint — a static site has no runtime to report on, so a 200 for a page nobody can render proves nothing. Probe failures open a GitHub issue with the failing output attached.

“If the infrastructure isn't good enough for your own portfolio, why would a customer trust you with theirs?”
